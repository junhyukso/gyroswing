# 개발 노트 — 확인된 사실, 버린 시도, 함정

실기기(사용자 아이폰 15 Pro, Windows PC) 녹화로 확인한 것만 적는다. 수치를 바꿀 땐 같은 녹화로 전후 비교하고 여기 갱신.

## 1. 방향(사용자가 정한 것)

- 웹 엔진(three.js), 아이폰, 처음엔 카메라 없이 "자이로로 최대한". 팔 모델은 안내형 보정에서.
- 마커·추가 부착물 거부. 폰 카메라 SLAM은 시작했다가 "사공이 많다"며 중단.
- 손 위치는 ZIG SIM Pro(ARKit)로 해결 중 → 다음은 자체 iOS 앱(docs/GRIP-APP.md).
- 막기 보정은 ARKit 기준이 잡혀 있으면 끄기(실제 위치만으로 막게).
- 일반 플레이의 손 배치를 막기처럼 유연하게: 설정 스위치(`blockAlways`)로(자동 아님).

## 2. 사파리 센서 (iOS)

- `rotationRate` alpha/beta/gamma = 기기 **x/y/z**축 회전 (명세의 z/x/y가 아님) → `Fusion.setPlatformHint` perm [2,0,1].
- `accelerationIncludingGravity` 부호 반대(`accSign` −1), `event.interval`은 초 단위.
- deviceorientation이 devicemotion보다 ~17 ms 늦게 옴. 방향은 ~60 Hz, 칼이 세로면 오일러 특이점.
- Wi-Fi 업링크는 몰려서 옴: p50 +4 ms, p95 +20–60 ms, 가끔 0.46 s, 손실 ~0.6%. 올바른 축 매핑이면
  +33 ms 예측 오차 3.5° RMS (예측 없으면 12.4°) — `node tools/analyze.mjs --known-map`.
- 사파리는 자가서명 CA로 **WSS를 거부**(페이지 경고 수락으로는 안 됨) → WebRTC 데이터 채널로 해결(잘 됨).
- 폰 페이지를 새로 고치면 폰 시계가 다시 시작 → Fusion이 시간 역행/큰 점프에서 리셋.

## 3. 손 위치 (자이로만으로는 모름)

- 팔 모델 = 칼 방향 → 손 위치. 떨림 필터(멈춤 2 Hz, β 10)로 멈춘 칼끝 떨림 3.7 → 0.8 mm.
- 가속도 이동: ZUPT + 회전 게이트(1–3 rad/s)가 필수(팔을 돌리면 폰이 가속돼 팔 모델과 이중 계산 → ~10 cm 표류).
  찌르기는 손목 회전이 섞이고(2.4–5.4 rad/s) 칼날 방향 가속(|a·b|≈0.9) → 칼날 방향만 0.45 s 최대값 게이트 5–8.
  결과 찌르기 13–23 cm. 'fused' 모델(기본): 측정 속도 − 팔 모델 속도를 한 번 적분, 큰 스윙이면 팔 모델 쪽.
- **버린 것**: 팔 모델이 만드는 가속도 빼기, 구심 레버 보정(실제 스윙에서 더 나쁨), 레버 반경으로 손목/팔 구분
  (0.12 vs 0.14 m, 큰 스윙도 손목 스냅으로 끝남), **가속도 이중 적분**(`tools/zupt.mjs`: 막기 녹화에서
  기본→막기→기본 닫힘 오차 p50 15–23 cm ≈ 움직임 크기 자체 — 진짜 멈춤이 없고 60 Hz로는 회전 중 오차가 큼).
- 막기(목각 기사): 사용자는 막을 때 팔 전체를 공격 쪽 **몸 바깥으로** 뺀다. 오른쪽 막기는 칼이 몸을 가로질러
  왼쪽 위를 향함 → 방향만 보는 팔 모델은 "손이 왼쪽"으로 읽음. → 칼+날 방향 전체로 막기 자세 원형(BLOCK_POSES),
  공격이 올 때만(백핸드 예비 동작이 오른쪽 막기와 똑같이 생김), 10–16 rad/s 넘어야 풀림(쳐내기 스냅 유지),
  공격 높이로 ±25 cm. 오른손잡이는 오른쪽에서 팔을 거의 안 빼므로 칼 기울기·날 방향으로 의도 판정(x ±0.34 m).
  녹화 재생 5/17 → 16/17 막음.
- 쳐내기 = 접촉 순간이나 직전 80 ms 안에 접촉 법선 방향 칼 속도 > 1.5 m/s, **입력(목표) 움직임**으로 판정
  (물리 칼은 서보 반동 때문에 가짜 쳐내기가 나옴).

## 4. 베기

- 자르기 = 물리 칼에서 ½·m_eff·v² ≥ 70 J (목표 칼 에너지의 ~1.7배, 서보 오버슈트), m_eff 0.35(손목)–1.5 kg(팔).
  실제 팔 스윙 15/15 자름, 손목 튕기기 2/42.
- 스윙 뒤 손 오프셋은 0.3 s에 가라앉힘(아니면 큰 스윙 뒤 ~11 cm 남음).
- 베기 수련 판정 = 정면 평면에서 벤 방향 각도 ±25°. 안내 화살표는 하늘색(금색은 짚단에 안 보임).

## 5. 네트워크 끊김 ("칼이 튄다")

- 렌더 성능이 아니라 **PC Wi-Fi 절전**(MediaTek MT7925, Power Saving=Auto): ~100 ms 배수 멈춤.
  게임이 10 ms마다 1바이트를 RTC로 보내 무선을 깨워 둠. 절전 끄기는 사용자가 `tools/wifi-lowlatency.bat` 실행.
- 고친 것: 예측이 멈춘 동안 서보 피드포워드가 마지막 각속도를 유지 → 칼이 날아감(`Fusion.advance`로 줄임),
  항상 켜진 가드 층이 0.7 m 손 튐(공격 있을 때만), 끊김 뒤 되돌아갔다 앞으로 튐(`staleHold`, `staleExtraMs` 60,
  `smoothMs` 20, `snapDeg` 180). 측정은 `tools/physjumps.mjs`(그려지는 물리 칼 기준 — 서보가 작은 목표 튐을 가림).

## 6. ZIG SIM / ARKit (아이폰 15 Pro, OSC)

- 멈춤·느릴 때 ARKit 위치 6–30 mm로 안정. **특징점이 적은 채로 계속 휘두르면**(빈 천장, 1–8점, 1.5–3 s) 몇 초에
  ~2 m 표류, 재인식 때 13–45 cm 튐. ARKit 포즈는 자이로보다 ~50 ms 늦음(`lead` 0.05 s).
- LiDAR 덕에 천장을 보고 가만히 있을 때(1–8점)는 정확 → 특징점 수를 단독 조건으로 쓰면 안 됨.
- 믿음 규칙(`arkit.js` params): 속도 < 2.5 m/s, 가슴에서 0.15–0.85 m, 방금 튀지 않음(>6 m/s 점프 후 0.3 s),
  회전 4–8 rad/s에서 서서히 끊음, 0.4 s에 2.2 rad 이상 돌면 스윙(0.35 s 끊음). '눈 감고 움직임' =
  특징점 < 12에서 움직인 시간을 빠르기로 가중해 쌓고(잘 보이면 0.5 s, 아니면 1 s에 잊음) 0.5 s치가 넘을 때만 0.4 s 끊고,
  안정 0.2 s 또는 특징점 ≥ 25가 0.3 s 보일 때까지 대기. 손 오프셋은 0.07 s로 따라가고 0.5 s로 풀림.
  - 막기는 타격 0.1–0.25 s 전에 3–8 rad/s로 움직여 들어가므로 빠르기 자체로 끊으면 늦음(3/9 → 6/9로 고친 이유).
  - 칼을 위로 들면 카메라가 천장을 봐서 특징점 1–16 → 예전 규칙은 높은 자세를 못 잡음(믿음 41% → 78%).
- 기준점: 처음 앞으로 겨누고 멈춘 자세를 '기본 자세'로, 그 자세(날 방향 포함 20° 이내)로 돌아올 때마다 팔 모델에
  다시 묶음(0.3 s), 그 외엔 10 s로 천천히.
- ZIG 터치(OSC)는 값 하나짜리 키가 닿아 있는 동안만 옴 — 예전 코드가 값 2개 이상 배열만 봐서 탭이 안 먹었음.
- ARKit이 믿어질 때 팔 모델과 30–70 cm 차이가 나는 경우는 대개 **팔 모델이 틀린 것**(왼쪽 세로 막기, 몸을 가로지른 수평).

## 7. 대결 튜닝 근거 (시뮬레이터)

- 시뮬레이터 스윙의 칼끝 최대 전진: 기본 자세 1.42 m, 내려베기 1.46, 사선 1.37, 수평 1.30, 올려베기 1.33, 찌르기 1.61.
  1.6 m에서 시작하면 기본 자세 칼끝이 상대 몸에 닿아 버려 새 접촉이 안 생김 → 1.8 m + 세게 휘두르면 0.4 m 내딛기.
- 가만히 든 칼에 상대가 걸어 들어온 게 '찌르기'로 잡혀서 → 판정은 상대 몸과의 상대 속도가 아니라 **때린 칼 자체 속도**.
- 시뮬레이터 내려베기는 접점 속도 27–37 m/s로 과장돼 있어 거의 다 최대치(35). 실제 폰으로 다시 맞출 것.

## 8. QA 방법

- **폰 없이 전체 경로**: 시뮬레이터(`btnSim`/`M`, `/duel?sim`). `?manual` + `game.advance(ms)`(결정적, 폰에 안 보냄).
- **숨은 브라우저 패널**: rAF 멈춤 + 크기 0 → 창 크기 지정 + `?timer`. 두 탭(방장+2P) 동시 실행은 `?pump`.
- **녹화 재생** (README "개발" 절에 전체 목록):
  - `tools/replay.mjs`, `analyze.mjs` — 사파리 녹화 채점(떨림·스윙 오차·지연·축 매핑)
  - `tools/zig-replay.mjs <녹화> [--timeline] [--recenter] [--set=키=값] [--seg=a-b]` — ZIG 녹화의 ARKit 믿음,
    못 믿은 이유(B 눈감음·S 안정 대기·W 스윙·J 튐·R 범위·G 기본 자세), 오프셋
  - `tools/zig-drift.mjs` — 기본 자세로 돌아올 때 ARKit 손과 팔 모델 차이(= 표류)
  - `tools/physjumps.mjs`, `jumps.mjs` — 칼 튐 / `tools/zig-send.mjs <녹화> [포트]` — ZIG 녹화를 UDP로 다시 보내 실기 없이 시험
  - 브라우저: `public/qa/blockharness.js` (`replayEvents`, `replayZig` — 막기 녹화를 원래 타이밍으로 게임에 재생,
    실제 결과와 대부분 같게 재현), `perfbench.js`, `judder.js`
- 회귀 기준으로 써 온 녹화(이 PC의 `recordings/`, git엔 없음): 막기 ZIG 06-35-34(8/8), 06-29-17, 베기 ZIG 06-37-59,
  표류 02-52-04(표류 구간 27–34 s는 믿음 0%여야 함).

## 9. 성능

사용자 PC는 RTX 5080: CPU ~1–2.5 ms, 1080p GPU ~1 ms. GTAO가 GPU 대부분(4K 4.4 → 반해상도 2.4 ms).
측정: `?prof`, H 키 HUD, `public/qa/perfbench.js`.
